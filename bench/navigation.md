# Navigation measurements

Use Node 24+ and an existing production build. The runner opens one Chromium page, blocks external requests, loads the read-only fixture from BENCH_MAP, and verifies navigation leaves world data unchanged and final styles exact. BENCH_DIST selects a preserved baseline build; BENCH_WORLDS=shared runs only the supplied shared fixture. BENCH_MAP_LABEL overrides its neutral label. The fixture SHA256 and optional response headers (BENCH_MAP_META, otherwise the .meta sibling) are recorded, so the comparator refuses different worlds.

Each pan-near, pan-wide and wheel-zoom gesture receives one warmup and three measured iterations by default. Each iteration first measures a matched idle rAF control. inputDispatchMs measures synchronous dispatchEvent/handler cost; callbacksMs records scheduled callbacks. Window-dispatched drag moves exercise captured D3 pan but bypass native hovered-SVG hit testing and tooltip behavior. These measurements are not physical-display FPS or input-to-photon latency.

At 16.7 and 8.3 ms budgets, rawIntervalsOverBudget counts strict threshold crossings. framesOverBudget permits 10% cadence jitter. missedBudgets sums max(0, ceil(interval / budget - 0.1) - 1), counting near-double intervals as one missed budget without flooring away a 33.3 ms interval against 16.7 ms. Compare both gesture and idle counters; a busy host or headless cadence can cause idle misses. Host load averages are contextual evidence, not an automatic pass/fail threshold.

BENCH_TRACE=1 traces the final measured iteration per gesture. Raw Chrome traces stay under /tmp/tupaia-butter-traces by default; BENCH_TRACE_DIR overrides that location. Compact attribution stays in the result JSON. Synthetic input start/end marks distinguish handler-nested layout even when Chrome omits synthetic EventDispatch records. Layout nested inside input or JavaScript provides forced-layout evidence. Main-thread style/paint, input and JS durations can overlap and must not be added. RasterTask totals span worker threads and represent aggregate task duration rather than frame wall time.

Selected browser SystemInfo GPU device/driver fields and featureStatus identify software versus accelerated rendering. Do not extrapolate a headless software-rendered result to a physical GPU display without a separate run. Browser tracing itself adds overhead; paired runs must use identical tracing settings.

Run node bench/navigation-compare.ts BASE.json HEAD.json for matched-world median summaries. It rejects incompatible environment, fixture, workload and missing samples. Use at least three samples for comparisons. The compact trace report can support diagnosis; raw traces in /tmp must be preserved elsewhere if needed across reboot.

Hardware calibration can use BENCH_CHANNEL=chromium BENCH_ANGLE=metal BENCH_GPU=1 (full installed Chromium rather than the default headless-shell). BENCH_HEADLESS=0 selects an offscreen headed window for explicitly authorized calibration only. Launch options and actual GPU status are recorded; an override does not prove hardware acceleration. Compare base/head only with identical backend and launch settings. Default software and calibrated results remain separate.

The first iteration of each world/gesture is retained separately in coldStarts (excluded from measured medians). It records first-input-to-first-rAF wait, first10 intervals and their maximum, plus the full interval/input samples. This is the first scripted gesture after map initialization and the matched idle control; it is not an immediate interaction before initialization or idle preparation. Preserve those cold metrics when evaluating a cache to avoid hiding first-gesture hitches with warm medians.

If window.MotionSurface is present, the runner reads its ready/active getters without activating the cache itself. Results retain active state for each gesture frame, readiness at start and total active frames. A transient surface remaining active after the gesture settles fails correctness validation. Head timings must report cache participation and cold hitches alongside warm medians.

The settled oracle explicitly invokes the normal drawScaleBar and fitScaleBar after active zoom styling, outside gesture timing. Final bar geometry/text must already match that precise renderer, so an interactive fast path cannot substitute approximate settled output.


Worker telemetry is recorded from `window.reliefWorkerStatus()` before each gesture and after settled tile publication: selected backend, completed jobs, pending jobs, uploaded atlas count and fallback reason. Per-frame dense pending flags and post-gesture publication wait are retained separately from gesture frame intervals.

Run `bench/navigation-quality.ts` with the same Metal flags for canonical save, label/relief hit, hatch, screenshot, cold threshold and stale-world checks. `BENCH_DISABLE_WORKER=1` disables both Worker and createImageBitmap before application initialization and requires the main-thread fallback to publish a tile and complete the same checks. A fresh identical SVG symbol alias forces an uncached first viewport-sprite decode; the harness delays that decode, checks pending bookkeeping and overview visibility, releases it, then requires tile publication and visibility handoff. It restores the alias and metadata before save or screenshot comparisons. This isolates the decoder handoff without relying on whether application boot populated the sprite cache.

The experimental worker requires `BENCH_RELIEF_WORKER=1`, which adds `?reliefWorker=1`. Omit it to test the default main-thread atlas. Set it together with `BENCH_DISABLE_WORKER=1` for the explicit capability fallback check. Worker timing is retained as an experimental regression dataset; do not enable it by default based on callback improvements alone.
